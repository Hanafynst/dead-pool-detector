Dead Pool Detector

"The price is a rumor. The sell simulation is the truth."

Paste a BSC token contract address into the CLI and get a verdict: is the pool actually alive — or is the displayed price a ghost?

Kiroween 2026 · Category: Frankenstein · Read-only · No wallet · No keys

What it checks

1 · Token basics

Reads totalSupply, decimals and symbol straight from the token contract.

2 · Pair resolution

Asks the PancakeSwap V2 factory for the token/WBNB pair (getPair). No pair means there is nothing to sell into.

3 · Real reserves

Reads the pair's actual reserves (getReserves) — the money that is really there, not a number a website displays.

4 · Sell simulation

Simulates selling a reference amount through the router (getAmountsOut) and compares it with the spot value implied by the reserves. The result is the exit ratio.

5 · Display cross-check (optional)

Give it the liquidity figure a site displays and the BNB price, and it estimates real liquidity as 2 × quote reserve × quote price — then compares.

Read-only by design

Every check is an eth_call. The tool never signs, never transacts, and never asks for a wallet or a key.

On the build-phase roadmap: PancakeSwap V3 pair probing (liquidity() / slot0), on-chain sell-tax reads, and owner-power / hidden-mint checks. The verdict engine you see below is the shipped core.

The verdicts

VerdictMeaning
ALIVEReserves are real and the simulated sell exits near spot.
RISKYThe pool lives, but the exit leaks value (exit ratio below 0.80 — tax or price impact), or the sell route cannot be simulated.
DEADReserves are zero or dust (under 0.001 WBNB) while supply exists, or a simulated sell returns almost nothing (exit ratio under 0.01).
LYING_DISPLAYReal reserves are under 1% of the liquidity figure being displayed. The price on screen is a costume on an empty pool.
NO_MARKETNo pair against WBNB on the main factory — there is no exit at all.

Use the CLI

The analysis core is detector.py — pure Python standard library, zero dependencies.

# Basic check (BSC, PancakeSwap V2):
python3 detector.py --chain bsc --token 0x<token-address>

# Cross-check a liquidity figure a website displays:
python3 detector.py --chain bsc --token 0x<token-address> \
                    --displayed-usd 13540 --quote-usd 880

# Options:
#   --pair <address>     use this pair instead of factory lookup
#   --sell-amount N      reference sell amount in token units
#                        (default: 1% of supply, capped at 10% of the
#                         pool's token reserve)
#   --rpc <url>          override the RPC endpoint
#   --json               JSON output only

# Run the test suite (mocked RPC, no network):
python3 -m unittest discover -s tests -v

Why this exists

Vetting free-mint and token offers by hand taught one expensive lesson: a displayed price is not proof. A token page can advertise five figures of "liquidity" while the pool contract holds nothing and a simulated full sell returns a fraction of a cent. Dead Pool Detector stitches the checks that catch that — pair, reserves, simulated exit, displayed-figure cross-check — into one verdict. A Frankenstein of a vetting pipeline, a price chart, and a lie detector.
